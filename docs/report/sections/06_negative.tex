\section{What did not work}\label{sec:analysis}

Three ideas failed their rules (Appendix~\ref{app:rules}). Ridge regressions from two sentence-embedding models to Rasch difficulty ranked items within a benchmark about as well as word counts did (Spearman 0.20 to 0.51), but averaged over the four held-out benchmarks, the correlation fell to between $-0.06$ and $0.04$. Question groups gave a subject its own offset for each group of items sharing their first feature field, such as a math competition, a website or a paper. Their net effect was small ($-0.0004$, SE 0.0004): they helped where that field names such a group, but on Multi-SWE-bench it names the programming language, and there they hurt by more than the rule allowed. I did not redefine the groups after seeing this, since that would have chosen the rule from the result.

The agent rule used $\lambda = 0$ for subjects run inside an agent harness, on the idea that the harness matters more for them than the model's release date. With one partner pair it cost $+0.0023$ (SE 0.0004), nearly all of it on Multi-SWE-bench, where 81 of 82 subjects run in an agent harness.

My harness predicted that a metadata prior helps at budget 0, and three hosted draws said it hurts (Section~\ref{sec:results}); this cost me more than any failed idea. I do not know which benchmarks are in the test pool, so I cannot say why: the hidden benchmarks may reward different subjects than the public ones, or the metadata may relate to strength differently there. The stress scenarios of the V5 test and the rule to check V5's budget-0 feedback against 0.25 were both responses to that failure.

Two mistakes cost time: an API-key check that would have made the first V4 build run as V3 on Codabench, caught before upload (Appendix~\ref{app:engineering}), and a bug in the V5 test's first run, found by my coding assistant and fixed before the rerun (Appendix~\ref{app:rules}).
