\section{Calling an LLM during scoring}\label{sec:llm}

V4 and V5 call the Anthropic API while Codabench scores them. When I built V4, the rules limited network access during scoring to ``approved inference APIs'' without naming them; after a probe had shown the API reachable and after my V4 upload, the organizers confirmed to me that Anthropic's API is one of them, and the rules now name it among eight providers. Hosted runs hide the submission's own output from participants, so I learned how the platform behaves from probe uploads (Appendix~\ref{app:engineering}). The platform does not install the packages in \texttt{requirements.txt}, so the submission talks to the API through Python's standard library, sending the same request body and API headers as the official client. The platform also restarts its workers at every budget, but files written in the submission folder stay there. The submission therefore keeps every reply in a file in its own folder, which all workers share (one file per item for ratings, one per subject and benchmark for guesses), with lock files so that each request is paid for once. A prediction waits at most 4 seconds for pending requests, and V5 sends guesses first because they are used from budget 0.

Because a single exception would fail the whole run, no failure raises an error; each falls back to a simpler model. A missing rating gives that item V3's treatment, and a missing guess gives that subject V4's prior. With no key, or no usable API, V5 predicts exactly as V3. Appendix~\ref{app:engineering} describes the failure handling, the tests and how the key is kept out of the repository. The request allows a server-side fallback from \texttt{claude-opus-5-5} to \texttt{claude-opus-4-8} (Appendix~\ref{app:prompt}), and the submission does not record which model answered. Offline all 1,473 saved replies (1,049 ratings and 424 guesses) came from Opus 5.5, but the bill for the V5 run shows \$0.06 for Opus 4.8, so the fallback answered a small share of its requests. Replies vary from call to call and the hosted ones stay in the scoring folder, which participants cannot read, so a rerun will not reproduce the feedback exactly.
